**D2 之後的模型修改（最終版，只有離線重播驗證，實機沒重跑 D2）**：
- 近期加權（τ 15 分鐘）：速度跟著最近的點。
- 預估誤差改成「速度會變」：σ 多 ½·a·Δ²（a = 0.08 ms／分鐘²，Δ = 距最後一點的分鐘數；D2 實際：5 分鐘後誤差 ±2 ms、15–20 分鐘後 13–20 ms）→ 排程約每 5 分鐘要一個點（有空檔時）。

- 靜止超過 10 分鐘（不聽了、半夜）不跑空檔短校正（否則每 5 分鐘在安靜的房間放一次測試音）；「連續播放 30 分鐘才倒數」從音樂恢復時重新累計。

為什麼木琴不行（錄音存檔離線分析）：
- **房間雜訊集中在低頻**：安靜段功率譜 300–600 Hz 比 4–7 kHz 高約 23 dB。木琴的能量集中在 523 Hz 基音，正好埋在雜訊裡；寬頻（決定時間精度）的只有 3 ms 的喀。
  雜訊脈衝把能量放在 300 Hz–7 kHz 全頻帶，2.5–7 kHz 的 SNR 有 15–30 dB。
- 原本的 GCC-PHAT 讓每個頻率等權重：木琴時大部分頻率只有雜訊，峰值被淹沒。已改成 **SNR 加權**（PHAT × 每個 bin 的 SNR/(1+SNR)，雜訊功率取自安靜段），
  實機等級模擬 −20 dB 從跳 4 ms 改善到 0.01 ms，但實機仍不夠。
- **這幾台喇叭的到達時間隨頻帶不同**（同一段錄音、雜訊脈衝分頻帶 GCC）：電視 全頻帶 +0.59 ms、4–7 kHz −0.03 ms；MSI 全頻帶 +0.13、3–7 kHz +1.41、4–7 kHz +0.80 ms。
  木琴能用的時間資訊只剩高頻（喀＋4.8 kHz 分音），量到的是「高頻的到達」，和雜訊量到的全頻帶到達本來就差 0.6–1.3 ms；
  電視在 4–7 kHz 木琴 −0.028、雜訊 −0.035 ms（兩者一致），證明差異來自喇叭色散，不是單純的偵測錯誤。
- **GLASS5+（放在 C270 旁、音量 31）**：雜訊脈衝完全聽不到（匹配濾波比安靜段 −1.5～−0.3 dB）；木琴聽得到（匹配濾波 +16 dB、4 個脈衝包絡相加 +10.7 dB），
  到達約比內建晚 590–600 ms，但包絡只定得到 ±10–30 ms，GCC 找不到 → **藍牙仍然量不到、沒有寫入、仍不出聲**。
  所以「藍牙寫入後音樂模式出聲」「隔 5 分鐘漂移」「出聲中 3 分鐘重取樣統計」這三項**都沒辦法做**。

「脈衝在兩個值之間跳」：
- 雜訊版今天 7 次（含 A/B 裡的雜訊脈衝）單台離散多數 ≤ 0.1 ms（內建偶爾 0.28–0.30 ms）；跳的時候跳到的值正好是**高頻段的到達**：
  D 寫入那次 MSI 5 個在 +0.12～+0.15、1 個在 +1.36 ms（= MSI 3–7 kHz 的到達 +1.41）；電視以前記錄的「差約 0.58 ms」＝全頻帶 +0.59 與 4–7 kHz −0.03 的差。
  也就是 GCC 曲線上有兩個差不多高的峰（低頻主導 vs 高頻主導），偶爾抓到另一個。**原因找到，但沒有修**（要決定「延遲」以哪個頻帶為準）。
- 木琴版更糟：單台離散 1–55 ms（不是改善）。
- 新的最大一致群規則讓這種跳動不會再讓整次寫入失敗（3／3 平手取較早的一群並註明；某台不穩只略過那台）。

**藍牙要校正得到，C270 必須用雜訊脈衝聽得到它**：需要 GLASS5+ 本身音量調大（它的按鍵），或校正期間系統音量高一些——兩者本程式都不會替使用者調。
